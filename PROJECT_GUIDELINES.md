## Documentation Standards

All documentation in this project must:

1. **Reference the Founder**: All docs should acknowledge Omran Khaled as the creator
2. **Maintain Professional Tone**: Technical, precise, and production-ready
3. **Be Current**: Update docs with code changes
4. **Be Structured**: Use markdown with clear hierarchy

### Core Documentation Files

| File              | Purpose                          | Maintenance                       |
| ----------------- | -------------------------------- | --------------------------------- |
| `README.md`       | Project overview and quick start | Update with new features          |
| `ARCHITECTURE.md` | System design and structure      | Update with architectural changes |
| `CONTRIBUTING.md` | Development standards            | Update with new conventions       |
| `OWNERSHIP.md`    | Intellectual property            | Update as needed                  |

### Documentation Principles

- **Clarity over cleverness**: Explain complex systems simply
- **Examples over explanations**: Show code, don't just describe it
- **Links over duplication**: Reference other docs instead of repeating
- **Current over comprehensive**: Accurate docs are better than exhaustive ones

## Code Standards

### Quality Gates

All code must pass:

- TypeScript strict mode compilation
- ESLint with zero warnings
- Prettier formatting
- Production build success

### Commit Standards

Follow [Conventional Commits](https://www.conventionalcommits.org):

- `feat:` New features
- `fix:` Bug fixes
- `docs:` Documentation changes
- `style:` Formatting changes
- `refactor:` Code restructuring
- `test:` Test additions
- `chore:` Maintenance tasks

### Branch Strategy

- `main` — Production-ready code, always deployable
- Feature branches from `main`
- PRs require review before merge
